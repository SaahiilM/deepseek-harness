# Agent Note：窄视口下侧边栏作为覆盖抽屉

Status: implemented

[English](2026-08-23-narrow-sidebar-overlay-drawer.md) | 中文

> 范围：仅 `ui-layout` —— AppFrame 在断点以下（`SIDEBAR_AUTO_COLLAPSE`，1024px）重新展开自动收起的侧边栏时如何渲染，以及哪些操作会将其关闭。让步链、宽布局的拖动手柄、store 偏好语义均未改变。

## 问题

窄视口下的重新展开此前仍把侧边栏留在其网格轨道中：在手机宽度（375–430px）上展开会把会话列挤压成一条细缝，使这套 Web UI 作为触控优先的界面几乎不可用。触控输入还继承了纯桌面的交互：指针拖拽调宽的命中条带横跨触控滚动路径，且打开线程后没有任何方式收起展开的面板。

## 决策

一句话：**断点以下，展开的侧边栏是覆盖抽屉——求解器仍然解析完整的侧边栏宽度，但框架将侧边栏网格轨道归零、把该列绝对定位覆盖在全宽中央列之上（位于 overlay 层之下），并渲染一层点击即关闭的遮罩。**

具体而言：

- 布局 store 新增一个动作 `closeNarrowSidebar`（只丢弃 `narrowExpanded`；宽视口下为 no-op）。toggle 的对偶语义、宽度偏好、`setNarrow` 的覆盖重置均保持不变。
- AppFrame 派生 `drawerOpen = narrow && !sidebarCollapsed`。抽屉模式下内联网格模板的首轨道为零，侧边栏列获得 `data-drawer-open` 与显式像素宽度；CSS 将其绝对定位并加边框与阴影。`'sidebar'` slot 的 owner 参数保持不变（`collapsed: false`、完整宽度），因此侧边栏注册方无法区分抽屉模式与宽模式。
- 抽屉展开时选择*另一个*会话会在绘制前关闭它（与详情栏自动关闭相同的 guard-ref 模式）。线程已是当前会话时打开抽屉不会触发自动关闭。
- 拖动手柄仅在宽视口渲染。

## Alternatives considered

- 保留挤压模型并缩小 `SIDEBAR_DEFAULT`：280px 的列配 390px 的会话区依然不可读，而且抽屉需求对宽布局毫无帮助。
- 由独立的移动端插件注册不同的 root 组合：为单一响应式关切维护两套外壳，违背 slot 系统的单组合模型。

## 后果

- 触控用户得到标准模式：列表 → 点击线程 → 全屏会话；控制栏始终一步可达。
- 桌面端渲染逐位一致：每个新属性、新元素和 CSS 规则都只在断点以下才可能出现的状态下生效。
